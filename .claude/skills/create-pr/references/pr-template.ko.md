# PR 본문 템플릿 (한국어)

`create-pr` 스킬이 `--lang ko`일 때 사용한다.
`<...>` 부분을 실제 내용으로 바꾸고 안내 문구는 지운다. 해당하지 않는 항목은 지우지 말고 `해당 없음`으로 쓴다.

## 템플릿

```markdown
## 요약

<이 PR이 무엇을 왜 바꾸는지 1~3문장>

## 변경 사항

- <변경 1>
- <변경 2>

## 변경 유형

- [ ] feat: 새 기능
- [ ] fix: 버그 수정
- [ ] refactor: 동작 변화 없는 구조 개선
- [ ] chore: 설정, 의존성, 빌드, 문서

## 테스트

- [ ] `bun run test` 통과
- [ ] `bun run lint` 통과
- [ ] `bun run build` 통과
- 추가/수정한 테스트: <파일 또는 해당 없음>

## 스크린샷 / 동작 확인

<UI 변경이면 스크린샷 또는 확인 방법, 아니면 해당 없음>

## 리뷰어 참고

<리뷰 시 집중해서 볼 부분, 트레이드오프, 알려진 한계. 없으면 해당 없음>

## 관련 이슈

<Closes #번호 또는 해당 없음>
```

## 작성 규칙

- 체크박스는 **실제로 실행해 통과를 확인한 항목만** `[x]`로 바꾼다. 실행하지 않았으면 `[ ]`로 두고 이유를 리뷰어 참고에 적는다.
- 변경 유형은 해당하는 것 하나만 체크한다. 여러 유형이 섞이면 가장 큰 비중의 유형을 고르고, 나머지는 변경 사항에 적는다.
- 변경 사항은 파일 나열이 아니라 동작 단위로 쓴다.
- 코드 식별자, 파일명, 명령어는 원문 그대로 둔다.
- 이모지를 쓰지 않는다.
